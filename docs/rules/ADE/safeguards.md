# Safeguards against runaway processes

Referenced from `docs/orca-workflow.md` § "Batch cycle". These rules are a preventive policy, mandatory because this project combines persistent processes with browser-based testing. The persistent processes are:

- the **Postgres container** (`podman run … postgres:17`) used for migrations, service tests and the E2E database;
- an optional **S3-compatible container** (e.g. MinIO) used to exercise `StorageProvider`;
- `next dev`, `next start` and `netlify dev`;
- Lighthouse CI's own server (`lhci autorun` / `lhci collect`), if a batch uses it;
- Playwright in UI or watch mode, and any `--watch` test runner (Vitest).

Production deploys, pushes, merges to `main` and any operation on a non-local database, bucket or auth provider never happen from a worker (see `phase-gates.md` rules 5, 9 and 11).

1. **Never combine a persistent server + a browser in the same worker.** Any testing task that needs the app served is split into two:
   - **Start:** the worker starts the container(s) and `next start` in the background on a free port, migrates and seeds the local DB, polls (`pg_isready` / `curl`) until ready or failed, and reports `worker_done` with only that result. It does not touch Playwright or Lighthouse.
   - **Test:** assumes the server and DB from the start task are up, runs Playwright/Lighthouse, and **stops the server (by PID or port) and the container(s)** before reporting `worker_done`.
   The same split applies to `next dev` and `netlify dev`: never in a worker that also drives a browser. Testing against a Netlify deploy preview URL needs no local server and is preferred whenever the preview exists.
2. **One container per worktree, on its own port.** Name it after the worktree (e.g. `core-pg-<worktree>`, `core-s3-<worktree>`) and pick a free port. Never share a container between worktrees and never reuse a port that is in use. A worker that starts a container removes it (`podman rm -f`) when its task ends, success or failure, and never touches containers it did not start. Containers hold only local MOCK data and no real credentials.
3. **Mandatory timeout on any task with a persistent process.** If the spec includes a container, `next dev`/`next start`/`netlify dev`, a watcher, or anything that doesn't terminate on its own, it must declare an explicit timeout (e.g. "if it doesn't respond in 60s, report `worker_done` with outcome=failed, do not wait longer"). Test runners always run once (`vitest run`, `playwright test`, never `--ui`/`--watch`). The Orchestrator uses a matching `check --wait --timeout-ms` and, if it expires, acts with `orca orchestration worker-stop` / `worker-abandon` — never leaves it running waiting for the user to close it by hand.
4. **Clean up the failed attempt before retrying.** If a task fails and is retried in a new worktree, first `worker-stop`/`worker-abandon` the failed dispatch, stop its server and containers, and `orca worktree rm` its worktree (if it has no changes worth rescuing) — never leave both alive in parallel. Free the ports and containers of the failed attempt before starting another.
5. **Concurrency cap.** Worktrees/agents alive at the same time for a batch should not exceed the number of planned packages + 1 (the orchestrator). If a retry would exceed it, clean up first (rule 4).
6. **Pre-trust every new worktree before dispatching the worker — it must never require a manual Enter.** Claude Code remembers by absolute path whether a folder was already trusted (`~/.claude.json` → `projects["<path>"].hasTrustDialogAccepted`). A fresh worktree path shows the "Do you trust the files in this folder?" dialog and blocks. Orca exposes no trust flag, so the orchestrator seeds `projects["<absolute-worktree-path>"].hasTrustDialogAccepted = true` in `~/.claude.json` **before** any `worker-start`/`worktree create` on a new path. One-time per path; the orchestrator's responsibility, not the dev workers'.
7. **Install dependencies once per worktree, never globally.** A worker that needs `node_modules` runs `pnpm install --frozen-lockfile` in its own worktree. Only the package that owns `package.json` in a wave may add dependencies and change `pnpm-lock.yaml`, and the Planner never puts two dependency-changing packages in the same wave — the lockfile would conflict at integration.
8. **Secrets and external services.** Never read, print or commit real secrets; never `cat` or `source` `.env.local`. Workers use only local values: the container's `DATABASE_URL`/`DIRECT_URL` (e.g. `postgresql://postgres:dev@localhost:<port>/core`), a mocked `AuthContext` or Clerk test mode configured by the human, and the local S3 container. Seed and admin scripts refuse a non-localhost database host; a worker never bypasses that guard.
